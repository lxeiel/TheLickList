# Recs Tab and Thanks Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the admin Recs inbox into its own tab with compact, searchable, expandable rows and batch dismiss, so 200 waiting recs don't bury the restaurant lists, and redesign the popup's thanks view.

**Architecture:** One new admin server action and data function delete many recs in a single parameterised query. `AdminBoard` gains a two-tab layout; `RecsSection` becomes the Recs tab panel holding search, selection and the batch bar as client state. The thanks view in `Recommend.tsx` is restyled and gains a Done button.

**Tech Stack:** Next.js 16.4 App Router, React 19, Supabase JS 2, CSS Modules, Vitest 4 (Node only), Phosphor icons.

**Spec:** [docs/superpowers/specs/2026-11-17-recommend-licks-design.md](../specs/2026-11-17-recommend-licks-design.md) — sections "The popup" (thanks view) and "Admin: the Recs inbox" / "Dismiss" (redesigned 2026-11-17). Builds on [2026-11-17-recommend-licks.md](2026-11-17-recommend-licks.md), already implemented on branch `recommend-licks`.

## Global Constraints

- Work on branch `recommend-licks` in its worktree. Nothing merges without Lex's go-ahead.
- Admin copy, verbatim: tabs "Restaurants" (count) and "Recs" (badge); "Select all"; search placeholder "Search recs"; "{n} selected"; "Dismiss selected"; "Dismiss {n} recs?" / "Dismiss 1 rec?"; "Yes, dismiss"; "Keep"; "Couldn't dismiss them"; "No recs waiting."; "No recs match."; "NOTES"; "{host} ↗"; "No Maps link"; existing per-row copy unchanged ("Add to Gotta Lick", "Dismiss", "Dismiss {name}?", "Couldn't dismiss it").
- Thanks copy, verbatim: "Thanks!", "I'll check it out.", "Recommend another", "Done".
- Batch limit: at most 200 ids per call (`REC_INBOX_CAP`); every id must pass `isRecommendationId`.
- Every admin action calls `requireAdmin()` first. Visitor text renders only as React text.
- Colours only from `app/globals.css` tokens, day and night. Phone breakpoint `(max-width: 767px)`; 44px tap targets on phones.
- Tests are Node-only; UI is verified in the browser by the controller.

## Review Focus

1. **Lex searches, ticks Select all, then clears the search.** Only the recs that matched stay selected; nothing hidden gets dismissed unseen (Task 2 browser check: select-all scope follows the search at the moment it's ticked, and the bar count is what gets dismissed).
2. **A batch where one id is malformed or repeated** (tampered request). Lex expects nothing deleted for a malformed id, and a repeated id handled once (Task 1 tests).
3. **Lex adds a rec to Gotta Lick while other recs are ticked.** The selection shouldn't silently include a rec that no longer exists (Task 2: selection is pruned to ids still present after refresh).
4. **An empty batch call** (e.g. a double click after the list refreshed). Lex expects a harmless refusal, not an error page (Task 1 test).
5. **Keyboard use of the tabs and rows.** Arrow keys move between tabs, Enter/Space expands a row, and focus stays visible (Task 2 browser check).

### Task 1: Batch dismiss

**Files:**
- Modify: `lib/recommendations.ts`, `lib/recommendations.test.ts`
- Modify: `app/reborn/(protected)/actions.ts`, `app/reborn/(protected)/actions.test.ts`

**Interfaces:**
- Produces (`lib/recommendations.ts`): `deleteRecommendations(ids: string[]): Promise<void>` — `.delete().in("id", ids)` with the service client; throws on a Supabase error.
- Produces (`actions.ts`): `dismissRecommendationsAction(ids: string[]): Promise<{ error?: string }>` — `requireAdmin()` first; refuses with `{ error: "Couldn't dismiss them" }` (deleting nothing) unless `ids` is an array with 1–`REC_INBOX_CAP` entries that all pass `isRecommendationId`; dedupes; calls `deleteRecommendations` once; `refresh()`; a thrown delete returns the same error.

- [ ] **Step 1: Write failing tests** in `actions.test.ts` (mock `deleteRecommendations` alongside `deleteRecommendation`; use valid UUIDs):
  - `"dismissRecommendationsAction refuses without an admin session"` — rejects `NEXT_REDIRECT`; `deleteRecommendations` not called.
  - `"dismissRecommendationsAction deletes each selected rec once"` — admin; `[A, B, A]` → `{}`; called once with `[A, B]`; `refresh` called.
  - `"dismissRecommendationsAction refuses an empty list"` — `[]` → `{ error: "Couldn't dismiss them" }`; not called.
  - `"dismissRecommendationsAction refuses if any id is malformed"` — `[A, "x' OR '1'='1"]` → error; not called.
  - `"dismissRecommendationsAction refuses more than 200 ids"` — 201 distinct valid UUIDs → error; not called.
  - `"dismissRecommendationsAction reports a failed delete"` — rejects → `{ error: "Couldn't dismiss them" }`; `refresh` not called.
