# Phase 3: Map + Filter + Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the placeholder homepage with the real public page: a Mapbox map and a restaurant list, both driven by live Supabase data, filterable by status and searchable by name/cuisine tags, with clicking a pin or a list row highlighting the other.

**Architecture:** `app/page.tsx` becomes a server component that fetches all restaurants once via the (already-built, previously unused) anon Supabase client, then hands that array to a single client component that owns filter/search/selection state and renders a Mapbox map and a list side by side. Filtering and search run client-side over the one fetched array — no refetching, no new API routes.

**Tech Stack:** Next.js (App Router, Server Components), `react-map-gl` + `mapbox-gl` (new), the existing `@supabase/supabase-js` anon client.

**Spec:** [docs/superpowers/specs/2026-10-26-lick-list-design.md](../specs/2026-10-26-lick-list-design.md) — this plan implements Phase 3 from that spec's Phasing section. Phases 1 (scaffold) and 2 (data model + admin auth) are already built and committed on `main` (through `b6ad0cd`, plus the Phase 3 spec commit `b09dde9`). Dishes UI and photo uploads remain Phase 4, out of scope here.

## Global Constraints

- Public reads use `getAnonClient()` (`lib/supabase.ts`, built in Phase 1, unused until now) — never the service-role client — per the spec's Architecture → Database access model.
- Status filter and search apply client-side to one fetched array, combined with AND (spec, Pages → `/`).
- Search matches restaurant name OR any cuisine tag, case-insensitive substring (spec, Pages → `/`).
- Clicking a pin opens a popup (name, status, rating, cuisine tags) and scrolls/highlights the matching list row; clicking a list row flies the map to and opens the popup for that row's pin, only when the row has coordinates (spec, Pages → `/`).
- A restaurant with no resolved coordinates (`lat`/`lng` null) has no pin but still appears in the list (spec, Pages → `/`).
- `NEXT_PUBLIC_MAPBOX_TOKEN` is client-safe by design (Mapbox restricts by URL referrer, not secrecy) — unlike the Supabase service-role key, it's fine in client code (spec, Architecture).
- No automated test suite — the spec's Testing section specifies manual verification; every task below verifies with a real command or a real browser check against a real (or temporarily-seeded) Supabase instance.
- Server components that read live data must be excluded from static prerendering in this Next.js version (established in Phase 1/2: Cache Components throws on `fetch`/`cookies()` during prerender otherwise) — `app/page.tsx` needs `export const instant = false;`.

## Review Focus

- A restaurant with `lat`/`lng` null must render in the list with no pin and no crash when the map renders — the most common real case, since not every pasted link resolves. Covered in Task 2 and Task 4.
- Selecting (via list click) a restaurant that has no coordinates must highlight its list row without the map erroring trying to fly to a nonexistent point. Covered in Task 4.
- A search with no matches must show an explicit "no restaurants found" state, not a silently empty map and list that look broken. Covered in Task 4.
- Search matching must be case-insensitive and match partial strings, not just exact/prefix matches — "ramen" must match "Ramen House" and a restaurant tagged "Ramen". Covered in Task 4.
- A missing/invalid `NEXT_PUBLIC_MAPBOX_TOKEN` must not crash the whole page (the list should still work) — covered in Task 2.

## Task 2: Map component

**Files:**
- Create: `app/MapView.tsx`
- Modify: `package.json` (new dependencies)

**Interfaces:**
- Consumes: `Restaurant` type from `lib/restaurants.ts`.
- Produces: `MapView({ restaurants, selectedId, onSelect, onDeselect }: { restaurants: Restaurant[]; selectedId: string | null; onSelect: (id: string) => void; onDeselect: () => void })`, a client component exported (default export) from `app/MapView.tsx`. `onDeselect` is called when the popup's close control is used (the prop type for `onSelect` requires a restaurant id, so closing needs a separate callback). Task 4 renders this component, passes `onSelect`/`onDeselect` to update shared selection state, and updates `selectedId` when a list row is clicked — which this component must react to by flying to and opening a popup for that restaurant.

- [ ] **Step 1: Install dependencies**

Run: `npm install react-map-gl mapbox-gl`

- [ ] **Step 2: Implement `MapView`**

`app/MapView.tsx`, `"use client"`. Behavior (the algorithm the props don't determine):

- Import `Map, Marker, Popup, type MapRef` from `react-map-gl/mapbox` and the CSS via `import "mapbox-gl/dist/mapbox-gl.css"`.
- Render nothing but a message ("Map unavailable — missing Mapbox token") in place of the map if `process.env.NEXT_PUBLIC_MAPBOX_TOKEN` is falsy (Review Focus: missing token must not crash the page).
- Otherwise render `<Map mapboxAccessToken={...} ref={mapRef} initialViewState={...} mapStyle="mapbox://styles/mapbox/streets-v12">`, with one `<Marker>` per restaurant that has non-null `lat`/`lng`, `onClick` calling `onSelect(restaurant.id)`.
- `initialViewState`: if any restaurant has coordinates, compute the min/max lat/lng across them and use that as the initial bounds (via the ref's `fitBounds` in a `useEffect` that runs once after the map loads, padding e.g. 40px) rather than hand-computing a center/zoom. If none have coordinates, fall back to a fixed `{ longitude: 0, latitude: 20, zoom: 1.5 }`.
- When `selectedId` changes to a restaurant that has coordinates: call `mapRef.current?.flyTo({ center: [lng, lat], zoom: 14 })` and show a `<Popup>` anchored at that restaurant's coordinates with its name, status, rating, and cuisine tags (comma-joined). When `selectedId` changes to a restaurant with no coordinates, or to `null`: no `flyTo`, no popup (Review Focus).
- The popup's `onClose` calls `onDeselect()`.

- [ ] **Step 3: Manual verification — renders with and without a token**

Write a temporary throwaway page (e.g. `app/map-test/page.tsx`) rendering `<MapView restaurants={[{...fixture with lat/lng...}, {...fixture with null lat/lng...}]} selectedId={null} onSelect={() => {}} onDeselect={() => {}} />` with two fixture restaurants — one with coordinates, one without. Run `npm run dev`, visit `/map-test`:
- With `NEXT_PUBLIC_MAPBOX_TOKEN` set in `.env.local`: expect one visible pin (for the restaurant with coordinates), map loads without console errors.
- Comment out/rename the env var temporarily and reload: expect the "Map unavailable" message instead of a crash.
Restore the env var, delete `app/map-test/page.tsx` when done (it's scaffolding for this task only, not part of the shipped app).

## Task 3: Restaurant list component

- [ ] **Step 1: Implement `RestaurantList`**

`app/RestaurantList.tsx`, `"use client"`. Behavior:

- Render an empty state — the text `No restaurants found` — when `restaurants.length === 0` (Review Focus).
- Otherwise render one row per restaurant: name, status, rating (if set), cuisine tags (comma-joined, if any), and "— no location set" when `lat` is null (matches the admin list's existing wording from Phase 2). Each row has `id={`restaurant-row-${restaurant.id}`}` and an `onClick` calling `onSelect(restaurant.id)`.
- A row whose `id` matches `selectedId` gets a distinct visual style (e.g. a CSS class or inline background) so the selection is visible.
- A `useEffect` watching `selectedId`: when it changes to a non-null value, call `document.getElementById(`restaurant-row-${selectedId}`)?.scrollIntoView({ behavior: "smooth", block: "nearest" })`.

- [ ] **Step 1: Implement `HomeClient`**

`app/HomeClient.tsx`, `"use client"`, `HomeClient({ restaurants }: { restaurants: Restaurant[] })`. Behavior:

- State: `status: "all" | "wishlist" | "tried"` (default `"all"`), `search: string` (default `""`), `selectedId: string | null` (default `null`).
- `filtered = restaurants.filter(r => (status === "all" || r.status === status) && (search.trim() === "" || r.name.toLowerCase().includes(search.trim().toLowerCase()) || r.cuisine_tags.some(tag => tag.toLowerCase().includes(search.trim().toLowerCase()))))` (Global Constraints: AND combination, case-insensitive substring on name or any tag).
- Renders: a status toggle (three buttons or a `<select>` — your choice, no spec requirement on which control) wired to `status`; a text `<input>` next to it wired to `search`; then `<MapView restaurants={filtered} selectedId={selectedId} onSelect={setSelectedId} onDeselect={() => setSelectedId(null)} />` and `<RestaurantList restaurants={filtered} selectedId={selectedId} onSelect={setSelectedId} />` below it.
